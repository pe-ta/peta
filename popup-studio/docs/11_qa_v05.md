# QA レポート v0.5（2026-10-15）

対象: v0.5 / v0.5.1（実験運用基盤: 仮説バックログ、結果取り込みと API、段階管理ボード、学びライブラリ、テンプレート 7 型）。
方法: コードレビュー（差分 `4b3198f..HEAD`、高精度）、Playwright E2E 5 本、API の境界値テスト、7 型の描画目視。

## 1. コードレビューで見つかり、直したもの（18 件）

| # | 症状 | 対応 |
|---|---|---|
| 1 | 二択タイル型が辛口分析で「ボタンが 1 本」と減点される | タイル型を多択として扱う |
| 2 | 仮説が複数の案に展開されるのに、1 案の結論で仮説全体が結論済みになる | 兄弟案が配信中・承認済み・提出中の間は結論にしない。勝ちが 1 つでもあれば勝ち |
| 3 | CSV の列検出が部分一致で、`campaign_id` を案 ID と誤認 | 完全一致を優先し、前方一致にフォールバック。`id` は完全一致のみ |
| 4 | CSV / API 経由ではタップ > 表示などの不正値が通る | 不正行を除外して応答と通知に列挙 |
| 5 | 全面写真型・吹き出し型のコントラスト検査が実際の面と違う | テンプレート側の面定義に 2 型を追加、見出し色も型ごとに取得 |
| 6 | 下書き再生成・案削除で仮説が「案を作成中」のまま残る | 削除時に仮説から案 ID を外し、空になれば未着手へ戻す |
| 7 | 引用符付き CSV（"1,200"）で列がずれる | RFC 4180 相当の分割に変更 |
| 8 | 書き込み API がクエリ文字列のトークンを受け付け、秘密鍵未設定でも動く | Bearer ヘッダのみ。本番で REVIEW_SECRET 未設定なら 503 で拒否 |
| 9 | 取り込みのたびにスナップショット全件を案ごとに再読み込み | ブリーフ単位で 1 回読み、最新値をメモリで追跡 |
| 10 | 経過日数の計算が 2 か所に重複 | stats の `daysSince` に統一 |
| 11 | 吹き出し型が自動選択されない（死にコード） | クイズ、相性診断 × 写真で選択 |
| 12 | 記入者を空で送ると既定の「AP」にならない | 空文字でも既定値を適用 |
| 13 | 日付の既定が UTC で、朝 9 時前は前日扱いになる | 日本時間の日付に統一 |
| 14 | 多択型・タイル型で指カーソルが描かれないのに GIF が生成される | その 2 型では指カーソルを点滅として描画し、重複セルを作らない |
| 15 | JSON 送信でスラッシュ日付が今日に化ける | 日付の正規化を共通化（`2026/10/5`、`20261005`、ISO を受理） |
| 16 | 配信中の案があると、確認待ち・承認後未配信の滞留アラートが出ない | 滞留判定を段階と独立に全項目で行う |
| 17 | 不明なテンプレート ID のプレビューが 200 で質問型を返す | 404 |
| 18 | テンプレート一覧の文言が「4 型」固定 | 件数を動的に |

## 3. 残っている弱点

1. **配信基盤との自動連携は未接続。** API は用意したが、基盤側の書き出し仕様が未確認。
2. **本番の REVIEW_SECRET が既定値のままだと、書き込み API は無効化される（設計どおり）。** Vercel で設定が必要。
3. **写真素材の置き場が無い。** 写真セルは LP の OG 画像か URL 入力に限られる。
4. **勝率の集計は結論数が少ないうちは参考値。** 5 件未満は「n小」と表示している。
5. **全面写真型の実写確認は本番で要確認**（この環境では外部画像を取得できない）。
