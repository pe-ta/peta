# QA レポート v0.3（2026-10-14）

「全体的にまだ使い物にならない・品質が低い」という指摘を受けて行った見直しの記録。
対象はコミット `v0.2`（勝ちポップアップ発見エンジン初版）から `v0.3` まで。

## 1. 見直しの観点

| 観点 | 誰の目線か | 確認方法 |
| --- | --- | --- |
| 生成物の見た目 | デザイナー・クライアント | 3 テンプレート × 訴求軸で PNG を生成し目視。LP 由来の薄いアクセント色（#98bfe6）や主色に近い色で破綻しないか |
| 導線 | AP | 初見で「次に何をすればいいか」が画面に出るか。空提出・不正入力時に何が起きるか |
| 本番環境での速度と整合性 | AP | Vercel のサーバーレス制約（関数時間、インスタンス分離、CDN）で壊れないか |
| 不正状態の防止 | 運用 | 配信中の案の編集・削除、承認なしの配信投入など、UI で隠しても API で通ってしまう操作がないか |
| コード品質 | 開発 | `tsc` / `eslint` / `next build`、ブラウザ E2E 3 本、コードレビュー（15 指摘） |

## 2. 直したこと

### 生成物の品質
- CTA の色を自動補正。薄い色は色相を保ったまま濃くし（灰色に濁らない）、主色と色相が近すぎる・無彩色の場合は CTA 向けの暖色から選ぶ。
- バッジ（55%OFF）と見出しの数字の二重表示を全テンプレートで解消。
- 画像が無い場合の装飾ビジュアルを新設（ブランド色の図形 + 数字入り吹き出し。吹き出しはテキスト幅に追従）。
- クーポン型テンプレートを追加（白いチケット面の文字色はブランド背景に依存せず常に濃色）。
- CTA に「›」を付け、ボタンらしさを上げた。
- ルールベースのコピーで「LINE限定…はLINEで」の重複、ターゲット文字列の生貼り（「30代男性、初めて検討、価格を比較中に選ばれる理由」）を修正。全角スペース・中黒区切りにも対応。
- 文字数チェックを全角換算に統一。

### 導線
- 各ブリーフに「次にやること」を 1 枠で表示（候補生成 → 辛口分析 → 提出 → 承認待ち → 配信投入 → 結果入力 → 昇格/終了 の状態から自動判定）。
- すべての操作に結果通知（成功・失敗）を表示。空のまま提出、必須欠落、表示回数を超える結果入力などは理由付きで拒否。
- 送信中のボタンはスピナー表示（二重送信防止）。
- 「下書きを再生成」「削除」は確認ダイアログ付き。
- ブリーフ編集画面を追加（勝ちの定義・オファー・ターゲット・配色・NG ワードなど）。
- 新規ブリーフの初期値を 3 訴求軸 × 2 レイアウト × 静止の 6 案に縮小（12 案は多すぎた）。

### 本番環境
- 画像をバージョン付き URL + CDN 長期キャッシュに変更。ブリーフ編集（配色・デバイス）でも URL が変わるようハッシュを付与。画像取得に失敗した劣化レンダリングはキャッシュしない。
- 一覧のサムネイルは常に静止 PNG（GIF は詳細ページのみ）。6〜12 枚の GIF 同時描画で数十秒待つ状態を解消。
- 重い操作のページに関数実行時間上限 60 秒を設定。
- AI の辛口分析は 1 回のクリックで 3 案ずつ処理し、残数を表示（12 案 × 15 秒で関数がタイムアウトしていた）。
- 本番で署名キーが既定値のときに警告を表示。

### 不正状態の防止（サーバー側）
- 配信中・終了した案の編集と削除を拒否。チャンピオンの削除を拒否。
- 承認済み以外の案の配信投入を拒否。手動の状態変更は 下書き ↔ 社内レビュー ↔ 差戻し のみ。
- 勝ち判定が出ていない挑戦者の昇格を拒否。勝率の計算を決定的（同じ入力なら同じ結果）にし、ボタンの活性とサーバー判定が一致するようにした。
- ブリーフ編集で仮説グリッド設定が消える不具合、空欄にした項目が旧値に戻る不具合を修正。
- 候補生成に失敗したときに空のブリーフが残って重複作成を誘う問題を修正（ブリーフ画面に戻して再生成を促す）。

## 3. 確認結果

| テスト | 内容 | 結果 |
| --- | --- | --- |
| `tsc` / `eslint` / `next build` | 型・静的解析・本番ビルド | すべて通過 |
| E2E: 実験ループ | 生成 → 辛口分析 → 提出 → 承認 → 配信 → 結果入力 → 勝ち判定 → 昇格 → 学びログ → ボード集計 | 通過 |
| E2E: 制作フロー | 12 案生成 → 編集で NG ワード検出 → 提出 → 承認/差戻し → ZIP 書き出し → 無効トークン 404 | 通過 |
| E2E: 見た目・導線 | 3 レイアウト生成、CDN キャッシュヘッダ、空提出の拒否、ブリーフ編集の往復 | 通過、コンソールエラーなし |
| 目視 | 画像主体 / テキスト主体 / クーポンの PNG を薄いアクセント色で確認 | CTA が鮮やかな暖色に補正され、吹き出し・バッジの重複なし |

## 4. まだ残っている弱点（正直に）

1. **コピーと辛口分析の質は API キー次第。** 未設定の本番ではルールベースで動くため、文言は定型的で辛口分析も「簡易判定」の域を出ない。`ANTHROPIC_API_KEY` を設定すると、訴求軸ごとの文言生成と画像を見た 6 軸採点に切り替わる。
2. **成果データは手入力。** 配信基盤からのエクスポート仕様が未確認のため、結果入力フォームで代替している。
3. **テンプレートは 3 型。** 業種別の雰囲気（医療の清潔感、EC の賑やかさ）までは持っていない。勝ちパターンが見えてから増やす方針。
4. **辛口分析の予測精度は未校正。** 実配信の勝敗との相関を取るまで「参考値」表記を維持する。
5. **承認ポータルの LP スクリーンショットは手動アップロード。** ヘッドレスブラウザを使わない構成のため自動取得していない。
6. **認証なし。** 社内ツール前提で、社内画面に認証を付けていない。公開 URL を社外に共有しない運用が前提。次の段階で Google Workspace SSO を付ける。

## 5. 再現手順（手元で確認する場合）

```bash
cd popup-studio && npm install && npm run build && PORT=3100 npm start
# 別ターミナルで（Playwright が必要）
node e2e/loop.mjs && node e2e/flow.mjs && node e2e/visual.mjs
```

E2E スクリプトはリポジトリ外（作業用ディレクトリ）に置いて実行した。必要なら `popup-studio/e2e/` に取り込む。
